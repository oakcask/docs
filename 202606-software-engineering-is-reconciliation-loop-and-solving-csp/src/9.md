## 第9章 組織や制度もまた「ソフトウェア的」である

この章では、組織や制度をソフトウェア的に見ることの有効性と危険性を論じる。組織のルール、承認フロー、職務分掌、評価制度、監査手続きは、人間の行動を制約し、誘導する。その意味で、制度は人間社会の上で動くソフトウェアのように振る舞う。

文献支柱として、Lessig の Code is Law、Policy as Code、Rules as Code、Infrastructure as Code を使う。Lessig は、アーキテクチャやコードが行動を規制することを論じた。Policy as Code や Rules as Code は、ポリシー、コンプライアンス、行政ルールなどを機械実行可能な形式で表現し、テストや自動適用の対象にする流れである。

この章の論点は次の通りである。

- ソフトウェア、組織、制度は、いずれも行動を制約し、望ましい状態へ誘導する設計物である。
- Policy as Code や Rules as Code は、制度設計とソフトウェア設計の境界を曖昧にする。
- ただし、人間を含む制度は Kubernetes controller のように単純には reconcile できない。

最後に、人間には解釈、納得、権力、感情、抵抗、学習があることを強調する。制度をソフトウェアのように見ることは有効な比喩であるが、制度を単なる自動制御対象として扱うことには危険がある。
