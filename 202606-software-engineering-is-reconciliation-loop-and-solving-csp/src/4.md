## 第4章 二重の reconciliation loop

この章では、reconciliation loop の難しさを扱う。あるべき状態が最初から完全に定義されているなら、ソフトウェアエンジニアリングは単なる実装問題に近くなる。しかし実務では、要求、価値、制約、環境仮定は不完全であり、実装と観測を通じて更新される。

要求工学の支柱として、Zave と Jackson の要求・仕様・環境仮定の関係を使う。要求は環境における望ましい条件であり、仕様は機械が満たすべき性質である。この関係により、「方針を満たす仕様を導く」という議論を支えられる。ただし、本稿の主張は、与えられた要求から仕様を導くだけでなく、何を要求とするかを経験的に決める上流の活動も含む。

この上流の活動を補強する文献として、Rittel と Webber の wicked problem、Dorst と Cross の problem-solution co-evolution、Ralph の Sensemaking-Coevolution-Implementation theory を使う。これらは、問題理解と解決案が同時に変化する設計活動を説明する。

この章の論点は次の通りである。

- 方針や要求は、実装前に完全に分かるものではない。
- 解を作ることで問題の見え方が変わり、問題の再定義が次の解を変える。
- したがって、reconciliation loop は現在状態をあるべき状態へ近づけるだけでなく、あるべき状態そのものを更新する学習ループでもある。
