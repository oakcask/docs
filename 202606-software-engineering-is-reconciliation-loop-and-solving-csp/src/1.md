## 第1章 導入：ソフトウェアエンジニアリングを「導く営み」として見る

この章では、レポート全体の主張を提示する。ソフトウェアエンジニアリングは、単にコードを書くことや要求を実装へ翻訳することではない。実務で行われているのは、ある望ましい状態を仮に定め、現在のシステムとの差分を観測し、その差分を小さくするようにシステムを変更し続ける活動である。

本稿では、この活動を reconciliation loop と呼ぶ。ここでいう reconciliation loop は、Kubernetes の controller に限定される技術用語ではなく、「望ましい状態」と「現在状態」の差分を検出し、変更を通じて両者を近づける反復的な営みを指す比喩である。初出時には、英語の reconciliation が「差異を調停し、整合させること」を含意することを脚注で補足する。

導入では、以下の問いを置く。

- ソフトウェアを変化する環境に適応し続けるものとして捉えるなら、エンジニアリングの中心は「完成」ではなく何になるのか。
- 方針や要求は最初から明確に与えられるものなのか、それとも実装と観測を通じて形成されるものなのか。
- 方針決定は単なる意思決定なのか、それとも複数の制約を同時に満たそうとする経験的な制約充足問題なのか。

章末では、本稿の中心命題として「ソフトウェアエンジニアリングとは、システムを reconciliation loop により導き、その方針決定のため制約充足問題を経験的手法で解くことである」と宣言する。
