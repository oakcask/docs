## 第8章 意思決定能力は才能ではなく、育てるべき専門職技能である

この章では、優れたソフトウェアエンジニアが行っている高度な意思決定を、才能ではなく専門職技能として扱う。対象は、プロダクト上の制約だけでなく、組織能力、チームの学習コスト、運用負荷、将来の変更余地、説明責任などを秤にかける判断である。

この判断は、周囲から見えにくい。成果が「起こらなかった障害」「増えなかった複雑性」「後で詰まらなかった移行」として現れることがあるためである。この論点は、失敗だけでなく物事がうまくいく条件に注目する Safety-II やレジリエンス工学と接続できる。

文献支柱として、Schön の reflective practitioner、Dreyfus と Dreyfus の技能獲得モデル、Collins らの cognitive apprenticeship、Lave と Wenger の situated learning、Ericsson らの deliberate practice、Klein の naturalistic decision making、Miller の評価ピラミッドを使う。

この章の論点は次の通りである。

- 意思決定能力は個人差を含むが、才能だけで説明すべきものではなく、訓練可能な専門職技能である。
- ジュニア・ミドルエンジニアには、制約を言語化し、熟練者の判断過程を観察し、小さく本物の判断に参加し、結果から反省する機会が必要である。
- 評価では、コード量や短期成果だけでなく、判断前の仮定、実行中の観測、事後の学習を見る必要がある。

AI によってコード生成が速くなるほど、この章の論点は重要になる。AI は実装案を増やすが、制約を秤にかける責任を消すわけではない。
