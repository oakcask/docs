## 第3章 reconciliation loop：現実をあるべき姿に向かって更新する

この章では、reconciliation loop の基本構造を定義する。基本形は、方針、要求、目標、制約としてあるべき状態を表現し、現在のシステム、利用状況、障害、組織状態を観測し、差分を解釈し、コード、設計、運用、組織プロセスを変更し、再び観測する、という循環である。

実例として Kubernetes controller を使う。Kubernetes controller は desired state と current state を比較し、現在状態をあるべき状態へ近づける control loop として説明される。この例は、reconciliation loop を単なる比喩ではなく、ソフトウェアシステムに実装された具体的な構造として示すのに適している。

補助的に、自己適応システムの MAPE-K loop を参照する。MAPE-K は Monitor、Analyze、Plan、Execute over Knowledge の略であり、監視、分析、計画、実行を知識基盤の上で回す自己管理システムのループである。初出時には略語を定義する。

この章の論点は次の通りである。

- reconciliation loop は、制御理論的には目標値と現在値の差分を扱うフィードバックループに似ている。
- ソフトウェアエンジニアリングでは、この差分はコードだけでなく、運用、組織プロセス、利用者行動にも現れる。
- 正しい解を一度に作るのではなく、観測可能な差分を縮め続けることがシステムを導く実務上の中心になる。

この章では、制御理論やサイバネティクスへ深く踏み込みすぎず、読者が実務上の構造として理解できる範囲に留める。
