# 第5章　構成要素：コード・履歴・テスト・設計記録の統合

## 概要

本章では、Codebase-Grounded Consensus を構成する具体的な要素を整理する。中心となるのは、コードベース、git 履歴、テスト、静的解析、arch test、linter、スキーマ、ADR、PR テンプレート、運用メトリクスである。

コードは実装上の真実を表し、テストは期待される振る舞いの証拠を表す。git 履歴は判断の時間的経緯を示し、ADR や PR は判断理由を補足する。arch test や linter は、設計上の制約を継続的に検証可能な形にする。

重要なのは、これらを個別のツールとして並べることではなく、「構造的主張」と「証拠」を結びつけることである。たとえば「domain 層は infra 層に依存しない」という主張は、ADR に記録するだけでは不十分であり、arch test によって継続的に検証されるべきである。

## 本章で扱う論点

- コードベースが保持する構造情報
- git 履歴が保持する時間的文脈
- テストと CI が提供する実行可能な証拠
- arch test / linter / static analysis の役割
- ADR / PR / issue による理由の記録
- 構造的主張と証拠のリンク
