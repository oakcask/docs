# 第9章　限界とリスク：二重管理、形式化コスト、AI の誤った確信

## 概要

本章では、Codebase-Grounded Consensus の限界とリスクを整理する。第一のリスクは、ADR、PR、C、コードの間に再び二重管理が発生することである。これを避けるには、C を人間が手作業で維持する独立文書にせず、コード・テスト・git・CI から可能な限り自動生成される派生物として扱う必要がある。

第二のリスクは、形式化コストである。すべての判断を厳密に記録しようとすると、開発速度が落ち、ドキュメント疲れが発生する。そのため、記録対象は、依存関係、アーキテクチャ境界、データモデル、ライブラリ選定、セキュリティ、移行、性能など、将来の変更コストや障害リスクが高いものに限定すべきである。

第三のリスクは、AI agent が誤った構造的主張をもっともらしく生成することである。これに対しては、AI の説明をそのまま信頼せず、テスト、静的解析、arch test、実行ログ、レビューによって検証する必要がある。

## 本章で扱う論点

- C が再び独立文書化する危険
- ドキュメントとコードの alignment cost
- 記録すべき判断と省略すべき判断の線引き
- AI agent による hallucinated rationale
- 自動生成された主張を検証する仕組み
- 人間の最終責任をどこに置くか
