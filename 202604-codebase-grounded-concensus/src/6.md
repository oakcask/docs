# 第6章　AI agent の役割分担：Builder ではなく複数の専門 agent へ

## 概要

本章では、AI agent を単一の「コード生成器」として扱うのではなく、複数の役割に分解する方法を提案する。AI agent が実装だけを担う場合、設計意図や制約の確認が不十分なまま変更が進み、人間のレビュー負荷が増大する。

そこで、Architect agent、Builder agent、Auditor agent、Historian agent、Reviewer Navigator という役割分担を導入する。Architect agent は変更前に構造的主張とリスクを列挙する。Builder agent はその制約内で実装する。Auditor agent はテスト、静的解析、arch test、依存関係検査を実行し、主張と証拠の対応を確認する。Historian agent は過去の git 履歴、ADR、障害記録、ライブラリ更新履歴を参照する。Reviewer Navigator は人間に対して、raw diff ではなく、影響範囲、証拠不足、不変条件の変更を提示する。

このように役割を分離することで、AI agent の出力を単なるコード差分ではなく、検証可能な設計変更として扱うことができる。

## 本章で扱う論点

- AI agent を単一の実装者として扱う危険性
- Architect / Builder / Auditor / Historian / Navigator の役割
- 実装前の structural claims の生成
- 実装後の evidence mapping
- 人間レビューの対象を raw diff から構造的リスクへ移す方法
