# 第3章　コンセンサス層 C への批判：UML 的失敗の再来可能性

## 概要

本章では、コンセンサス層 C に対する批判的検討を行う。第一の批判は、C がコードとは別の source of truth として扱われた場合、UML やモデル駆動開発が直面してきた問題を再発する可能性があるという点である。

現実のソフトウェアは、依然としてプログラミング言語、ライブラリ、フレームワーク、データベース、CI/CD、運用環境の上で動作している。高水準のモデリング言語は、抽象的な設計を表現するには有用であっても、実際の運用上の例外、パフォーマンス制約、ライブラリ固有の挙動、移行過程の複雑性を十分に表現できないことが多い。

第二の批判は、論文がコードを「一次元のテキスト」として過度に低く評価している可能性である。現代のコードベースは、型、モジュール、依存関係、インタフェース、テスト、スキーマ、設定、CI などを通じて、多くの構造的情報をすでに保持している。

したがって問題は、コードに表現力がないことではなく、コード・履歴・テスト・設計判断・運用証跡が統合的に参照されていないことにある。

## 本章で扱う論点

- C を source of truth にした場合の危険性
- UML やモデル駆動開発との類似点
- 抽象モデルと実行可能コードの乖離
- コードがすでに持つ構造的表現力
- 本当に不足しているのは「根拠」と「履歴」の接続であること
