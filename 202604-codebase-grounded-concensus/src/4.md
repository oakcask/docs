# 第4章　代替方針：Codebase-Grounded Consensus

## 概要

本章では、コンセンサス層 C をコードの外部にある独立した真実として扱うのではなく、コードベースを中心に再構成される派生的な合意層として位置づける方法論を提案する。この方法論を、Codebase-Grounded Consensus と呼ぶ。

Codebase-Grounded Consensus では、source of truth はあくまで、実行可能なコード、テスト、型、スキーマ、設定、マイグレーション、git 履歴、CI 結果、運用ログに置かれる。設計意図や判断理由は ADR、PR、issue、dependency decision record などに記録されるが、それらは単独で真実になるのではなく、コードやテストとリンクされることで意味を持つ。

この考え方では、C はコードを置き換えるものではない。C は、コードベースから抽出された構造情報と、人間が記録した設計判断を結合する「索引」「レビュー面」「合意台帳」として機能する。

## 本章で扱う論点

- source of truth をコードベース側に置く理由
- C を一次成果物ではなく派生成果物として扱う方針
- コード、テスト、git、ADR、運用証跡の統合
- 実行可能な証拠に基づく合意形成
- Codebase-Grounded Consensus の基本原則
