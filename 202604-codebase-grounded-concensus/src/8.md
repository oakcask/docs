# 第8章　メトリクス：合意形成の品質をどう測るか

## 概要

本章では、Codebase-Grounded Consensus の有効性を測るためのメトリクスを定義する。AI agent の導入効果は、単純な PR 数、実装速度、コード生成量だけで測るべきではない。むしろ、構造的主張がどれだけ証拠に接続されているか、設計意図がどれだけ追跡可能か、人間のレビュー負荷が下がっているかを測る必要がある。

代表的な指標として、claim coverage、unsupported claim count、architecture drift rate、rationale coverage、intervention distance、diagnosis latency を用いる。これらに DORA metrics や SPACE framework の観点を組み合わせることで、速度、品質、認知負荷、協調のバランスを見る。

本章では、AI agent の生産性を「どれだけ速くコードを書いたか」ではなく、「どれだけ安全に、説明可能に、将来変更可能な形でコードベースを進化させたか」として評価する。

## 本章で扱う論点

- AI agent の成果を PR 数だけで測る危険性
- claim coverage
- unsupported claim count
- architecture drift rate
- rationale coverage
- intervention distance
- diagnosis latency
- DORA / SPACE との接続
