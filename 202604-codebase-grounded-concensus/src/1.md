# 第1章　序論：AI agent 時代に失われる「設計意図」

## 概要

本章では、AI agent を用いたソフトウェア開発において、実装結果としてのコードは生成される一方で、「なぜその構造になったのか」「どの不変条件を前提にしたのか」「なぜそのライブラリを選んだのか」といった設計意図が記録されにくい、という問題を定義する。

従来の人間中心の開発では、設計意図はレビュー、口頭説明、issue、PR、ADR、過去の経験などに分散して存在していた。しかし AI agent が実装主体として関与する場合、コード変更の速度が上がる一方で、意図・制約・代替案・根拠が暗黙化しやすくなる。

ここでいう PR は、GitHub の Pull Request を代表例とする変更提案単位であり、GitLab では Merge Request（MR）に相当する。

本レポートでは、この問題を「コードと設計判断の乖離」と捉え、AI agent が生成するコードを人間が安全にレビューし、将来の変更に耐える形で維持するための方法論を検討する。

## 本章で扱う論点

- AI agent による開発で何が見えにくくなるのか
- コードだけでは把握しにくい情報とは何か
- 設計意図、不変条件、依存関係、ライブラリ選定理由の重要性
- 人間のレビュー負荷と認知負荷の増大
- 本レポートの目的と射程
