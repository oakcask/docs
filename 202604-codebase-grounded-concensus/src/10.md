# 第10章　結論：コードを中心にした合意層の設計

## 概要

本章では、レポート全体の議論を総括する。対象論文が提案するコンセンサス層 C は、AI agent 時代の重要な問題を指摘している。すなわち、AI が生成したコードには、設計意図、不変条件、選択理由、代替案、リスク評価が十分に残らないという問題である。

しかし、C をコードとは別の source of truth として扱うと、UML やモデル駆動開発が直面した抽象モデルと実装の乖離を再発する可能性がある。したがって、より現実的な方向は、コードベース、git 履歴、テスト、arch test、linter、ADR、PR、運用証跡を統合し、C をそれらから導かれる派生的なレビュー面として扱うことである。

本レポートの結論は、次の一文に要約できる。

> コードは真実であり、テストは証拠であり、git は時間軸であり、ADR は理由であり、コンセンサス層はそれらを横断して AI と人間がレビュー可能にする派生インデックスである。

この方法により、AI agent の速度を活かしつつ、人間が設計責任を保持し、ソフトウェアを変更可能で説明可能な形に維持することができる。

## 本章で扱う論点

- 論文の問題意識の再評価
- C を source of truth にしない理由
- Codebase-Grounded Consensus の要約
- AI agent 時代における人間の設計責任
- 今後の研究・実践上の課題
