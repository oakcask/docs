## 13. Case Studies: ケーススタディ

### 含める内容

- 提案言語がどのように有利になるかを、具体的なケースで示す。
- すべてのケースで、Ruby / Python / TypeScript / Rust / Elixir との比較を行う。

### ケース案

#### Case 1: 簡易 Git 実装

- Endoh 氏のベンチマークに近い題材を再現する。
- ファイル操作、hash、index、commit log、diff を扱う。
- 提案言語の標準ライブラリと contract がどこで効くかを見る。

#### Case 2: Web API + 永続化

- 入力 schema、DB effect、transaction、validation を扱う。
- 型と contract の境界指定が有効かを見る。

#### Case 3: 既存コードへの仕様追加

- 既存モジュールを読み、機能追加する。
- dependency graph と affected tests が context size を削減するかを見る。

#### Case 4: バグ修正

- failing test を与え、エージェントが最小修正できるかを見る。
- 構造化診断の効果を測る。

#### Case 5: ドキュメント同期

- API変更時に doctest / doc / contract が同期されるかを見る。
- doc drift detection の有効性を評価する。
