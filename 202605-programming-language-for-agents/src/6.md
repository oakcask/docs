## 6. Syntax Design: 表層構文の設計

### 含める内容

- 構文の方針を説明する。
  - 短い。
  - 読める。
  - インデント・ブロックのルールが安定している。
  - 記号過多にしない。
  - メタプログラミングを無制限に許さない。
- 「生成 token 数」と「読解 token 数」の両方を設計対象にする。

### 議論すべき論点

- `do ... end` と indentation のどちらを採るか。
- pipeline operator を標準にするか。
- method chain と pipeline の使い分け。
- block / lambda / anonymous function の統一。
- exception より Result 型を基本にするか。
- null / nil を許すか、Option 型にするか。
- macro / DSL をどこまで許すか。
- implicit return を許すか。

### 評価観点

- 同じ処理を Ruby / Python / Elixir / TypeScript / Rust と比較したときの LOC。
- 生成 token 数。
- 修正時の diff サイズ。
- AST の単純さ。
- エージェントが構文エラーから復帰できるか。
