## 12. Evaluation Methodology: 評価方法

### 含める内容

- この言語設計が本当に AI生成に有利かを測る方法を提案する。
- 単純な Pass@k だけでなく、生成・修正・保守の総合指標を使う。

### 評価指標

| 指標 | 内容 |
|---|---|
| Time-to-green | テストが通るまでの時間 |
| Cost-to-green | API / token コスト |
| Iterations-to-green | 修正ループ回数 |
| Generated tokens | 初回生成 token 数 |
| Repair tokens | 修正時 token 数 |
| Diff size | 修正差分の大きさ |
| LOC | 実装行数 |
| Test pass rate | テスト成功率 |
| Diagnostic usefulness | エラー診断から修正できる割合 |
| Context size | エージェントが読む必要のあるファイル量 |
| Regression rate | 既存機能を壊す割合 |
| Human review time | 人間がレビューに要する時間 |

### 比較対象

- Ruby
- Python
- JavaScript
- TypeScript
- Elixir
- D
- Rust
- Go
- 提案言語

### タスク設計

- 小規模 CLI 実装。
- JSON / TOML 設定パーサ。
- HTTP API。
- DB migration。
- 既存コードへの機能追加。
- バグ修正。
- リファクタリング。
- contract 追加。
- 仕様変更への追従。

### 実験条件

- 同じモデル。
- 同じプロンプト。
- 同じテスト仕様。
- 同じ最大試行回数。
- 同じ外部ライブラリ制約。
- 同じ実行環境。
- 複数回試行し、平均・分散・失敗率を見る。
