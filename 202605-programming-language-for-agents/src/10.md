## 10. Module and Documentation Model: モジュール・文書・合意

### 含める内容

- モジュールを AIエージェントの作業範囲を限定する単位として設計する。
- コードとドキュメントを分離しすぎると alignment cost が増えるため、モジュール内に最小限の機械可読メタデータを持たせる。

### モジュールに含める情報

- module name
- public API
- invariants
- effects
- dependencies
- examples
- tests
- migration notes
- design rationale
- ownership / responsibility boundary

### 例

```text
module Billing.Invoice
  purpose "Create and validate invoices before persistence"

  depends_on
    Billing.Customer
    Money
    Time

  invariant "total equals sum of line item amounts"
  invariant "issued invoice cannot be mutated"

  effect db: write
  effect time: read

  pub fn issue(customer: Customer, items: List<Item>) -> Result<Invoice, InvoiceError>
end
```

### 議論すべきこと

- ADR-lite を言語に含めるか。
- doc comment と contract の重複をどう避けるか。
- 仕様コメントを実行可能にする方法。
- 生成されたドキュメントとコードの drift をどう検出するか。
