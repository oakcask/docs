## 14. Discussion: 考察

### 含める内容

- 設計上のトレードオフを議論する。

### 議論すべき論点

#### 14.1 動的性と静的性のトレードオフ

- 動的性は初回生成を速くする。
- 静的性は大規模修正を安全にする。
- 提案言語では、公開境界・副作用境界・永続化境界で静的性を強める。

#### 14.2 簡潔性と暗黙性のトレードオフ

- Ruby 的な短さは有効だが、過剰なメタプログラミングは hidden dependency を増やす。
- DSL は許すが、展開結果・型・依存を取得可能にする。

#### 14.3 人間向け最適化と AI向け最適化

- 人間に読みやすいコードと AIに扱いやすいコードは重なる部分が多い。
- ただし、AIには構造化診断、JSON出力、dependency graph など追加の機械可読情報が必要。

#### 14.4 小規模タスクと大規模コードベース

- 小規模タスクでは Ruby/Python 的な短さが効く。
- 大規模コードベースでは、型・契約・モジュール境界・影響範囲分析が重要になる。
- 提案言語は、スクリプトからモジュール化プロジェクトへ段階的に移行できる必要がある。
