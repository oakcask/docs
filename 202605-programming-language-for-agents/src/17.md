## 17. Conclusion

### 含める内容

- 本レポートの主張を再提示する。
- 「AIが高速に生成できる言語」は、単に動的型付けで短い言語ではない。
- 重要なのは以下であるとまとめる。

### 結論の骨子

- AIエージェントの生成速度は、出力 token 数だけでなく、実行・診断・修正ループの短さで決まる。
- Ruby/Python 的な簡潔性は有効だが、大規模化には検証性が必要である。
- Elixir 的な pipeline と統一ツールチェーンは、AIの作業単位を明確にする。
- D 的な contract / unittest は、仕様と検証をコード近傍に置く点で有効である。
- typed holes と構造化診断は、AIエージェントにとって次の一手を決めるための重要なインターフェースになる。
- したがって、提案言語の中心原理は以下である。

```text
短く書けること。
局所的に検証できること。
失敗から修正までの距離が短いこと。
人間とAIが同じコードを読めること。
```
