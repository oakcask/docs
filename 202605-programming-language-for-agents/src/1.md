## 1. Introduction: 問題設定

### 含める内容

- 背景を説明する。
  - AIエージェントによるコード生成では、言語の記述量、型検査、ビルド設定、依存関係、テスト実行、エラーメッセージ読解が総コストになる。
  - Yusuke Endoh 氏の Claude Code ベンチマークでは、簡易 Git 実装において Ruby・Python・JavaScript が高速・低コスト・安定という結果が報告されている。ただし、これは小規模プロトタイピング規模の実験であり、大規模開発での結論ではない。
- 問題を定式化する。
  - 従来のプログラミング言語は主に「人間が書く」「人間が読む」「コンパイラが実行可能コードに変換する」ことを中心に設計されてきた。
  - AIエージェント時代には、「エージェントが短い試行錯誤ループで安全にコードを生成・修正できるか」が新しい設計軸になる。
- 本レポートの問いを置く。

### Research Questions

- **RQ1:** AIエージェントが高速にコード生成できる言語には、どのような記法的・意味論的特徴が必要か。
- **RQ2:** 動的言語の短さと、静的言語の検証性はどのように両立できるか。
- **RQ3:** エージェントの修正ループを短縮するために、コンパイラ・テストランナー・言語サーバはどのような情報を返すべきか。
- **RQ4:** このような言語の有効性は、どのようなベンチマークと評価指標で測定できるか。
