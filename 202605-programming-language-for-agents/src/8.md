## 8. Typed Holes and Partial Programs: 穴を持つプログラム

### 含める内容

- typed holes を AIエージェント向けの第一級機能として定義する。
- 「未完成コードは壊れたコードではなく、情報を持つ作業状態である」と位置づける。

### typed hole が返すべき情報

- hole の位置。
- 期待される型。
- スコープ内で使える変数。
- 使えそうな関数。
- 関連する contract。
- 関連する failing tests。
- 典型的な補完候補。
- 安全な autofix の候補。
- その hole を埋めないと失敗するテスト一覧。

### 含めるべき例

```text
fn parse_config(path: Path) -> Config
  raw = fs.read_text(path)
  config = _
  ensure config.port in 1..65535
  config
end
```

この hole に対して、コンパイラが以下を返す設計を示す。

```json
{
  "hole": "_",
  "expected_type": "Config",
  "available_bindings": ["raw: String", "path: Path"],
  "candidate_functions": ["toml.parse", "json.parse", "Config.from_map"],
  "related_tests": ["config_test.loads_valid_file", "config_test.rejects_invalid_port"]
}
```
