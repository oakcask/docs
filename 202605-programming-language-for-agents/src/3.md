## 3. Design Goals: 言語設計目標

### 含める内容

- 設計目標を明確に列挙する。
- それぞれについて、人間向けの利点と AIエージェント向けの利点を分けて書く。

### 設計目標

| 目標 | 内容 |
|---|---|
| G1. 高い意味密度 | Ruby/Python のように短いコードで仕様を表現できる |
| G2. 低いセットアップ摩擦 | 1ファイルで即実行でき、標準ツールだけで test / format / typecheck ができる |
| G3. 明白な標準スタイル | 同じ処理に対する書き方の分散を抑える |
| G4. 局所的な静的検査 | 公開境界・I/O・永続化・危険操作では型と契約を強める |
| G5. typed holes | 未完成部分を明示し、期待型・利用可能値・関連テストを返す |
| G6. 構造化診断 | エラーを自然文だけでなく JSON / AST span / fix candidate として返す |
| G7. 実行可能仕様 | doctest, property test, contract, examples を言語に近接させる |
| G8. 影響範囲の局所化 | 変更対象ファイル、依存、テスト範囲を機械的に絞れる |
| G9. 大規模化可能性 | 小規模スクリプトからモジュール化されたプロジェクトへ移行できる |
| G10. AIと人間の共通可読性 | AIにだけ都合のよい中間表現ではなく、人間も読めるソースコードを保つ |
