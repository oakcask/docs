## 第6章 表現としての言語：命名、API、図、グラフ、ビュー

### 目的

「言語」を一次元テキストに限定せず、ソフトウェア理解と設計を支える表現体系全般として拡張する。

### 含める内容

- プログラミング言語は、設計言語の一部にすぎない。
- 命名、型、API、ディレクトリ構造、モジュール境界、テスト名、Architecture Decision Record、図、依存グラフは、いずれもシステムを記述する言語である。
- UML はグラフィカルなモデリング言語であり、アーキテクチャビューはステークホルダーの関心を分離する言語である。
- Program Dependence Graph や Code Property Graph は、コードを制御依存、データ依存、構文構造として再記述する非テキスト言語である。
- 図は単なる説明補助ではなく、探索、推論、注意配分の構造を変える認知的道具である。
- よい表現は、対象世界を正確に写すだけでなく、人間が誤りにくく、変更しやすく、検証しやすい形にする。
